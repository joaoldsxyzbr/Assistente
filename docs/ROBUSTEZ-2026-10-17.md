# Robustez incremental — 17/10/2026

## Objetivo e escopo
Manter o **Assistente MCPs em JavaScript puro (ES Modules)**, com os MCPs oficiais GitHub e Cloudflare, OAuth independente e skills Ponto, Gastos e Desenvolvimento. Não reescrever arquitetura nem adicionar bibliotecas sem necessidade. Este documento registra decisões, implementação, validação e operação.

## Achados confirmados e decisões

| Área | Situação anterior | Intervenção |
| --- | --- | --- |
| Respostas remotas | Normalização textual recusava saídas acima de 64 KiB, mas depois da leitura do corpo HTTP | Limitar a **2 MiB** durante o streaming de cada resposta upstream, inclusive OAuth; 64 KiB continuam sendo o limite de saída textual |
| Catálogo GitHub (~95 ferramentas) | Lista inteira com schemas (~269 KB observados) | Listar **20 nomes e descrições resumidas** por página; `name` obtém schema completo sob demanda; `query`, `cursor`, `limit` disponíveis |
| Protocolo MCP | Cliente usava handshake padrão | `versionNegotiation: { mode: "auto" }` para moderno + fallback legado |
| Rate limiting | Só OAuth e timeout sem cota por conta | Binding nativo Cloudflare: 120 chamadas por 60 s por operador autenticado; 15 tentativas de formulário por 60 s por endereço de origem |
| Diagnóstico | Logs de requisição e falhas OAuth | Adicionar eventos `remote_discovery` e `remote_call` com provedor, resultado, tempo e incerteza; **sem nomes de ferramentas, parâmetros ou tokens** |
| Ambiente | Preview e produção já possuem KV separados | Separar também os namespaces dos rate limiters em cada ambiente |
| OAuth/PKCE/CIMD | Já implementados | Preservar; reforçar por testes e aceites reais, sem substituir a autenticação oficial |

**Decisões deliberadas:** não fazer caching de tokens ou resultados privados; não repetir automaticamente operações de escrita; não mudar escopos Github autorizados sem decisão específica; não criar proxy novo; não criar GitHub Actions que exijam salvar credenciais Cloudflare em GitHub. O OAuth do MCP do Assistente já anuncia suporte a CIMD pelo SDK; a autenticação específica do upstream Cloudflare permanece baseada em descoberta e DCR do provedor.

## Segurança e limites

- `server/shared/upstream-http.js`: streaming com limite de entrada impede acumular grandes corpos em memória. Respostas `Content-Length` maior que o limite são recusadas antes da leitura; streaming sem `Content-Length` para no teto. Falha segura sem truncamento silencioso; a consulta deve ser restringida/paginada.
- `server/remote-tools.js`: saída somente textual, no máximo 64 KiB, filtros e paginação do catálogo. Chamada genérica segue exigindo `mcp:write` mesmo quando o nome remoto parece de leitura.
- Rate limiting é **por localidade da rede Cloudflare**, não um contador global perfeito; mede chamadas no Worker, não no MCP upstream. Chave autenticada vem do OAuth validado, nunca do usuário arbitrário nem do bearer token. Formulários sem autenticação usam o endereço informado pela borda Cloudflare; alguns usuários atrás de NAT podem dividir cota. Sem binding no ambiente local o controle é desativado nos testes; produção/preview devem possuir bindings.
- Falhas ao consultar o rate limiter retornam 503 (falha fechada), sem liberar autenticação por engano.
- Dados de D1 nunca são usados para testes de escrita; IDs das skills permanecem iguais; tokens não são impressos.
- Limite de resposta upstream de 2 MiB pode rejeitar consultas grandes **inclusive textuais**: usar filtros, paginação e consultas mais específicas. Não elevar o limite sem observar memória e contexto.

## Interfaces

`mcp_github_tools` e `mcp_cloudflare_tools`:
- Sem argumentos: retorna até 20 ferramentas (`name` e `description`) + `total` e `nextCursor`.
- `{ "query": "get file" }`: pesquisa palavras separadas no nome e na descrição, sem exigir frase contígua; correspondências no nome são priorizadas, recorrendo à descrição quando necessário.
- Quando a busca retorna **uma única ferramenta**, inclui seu `inputSchema` se couber em 16 KiB; isso evita outra chamada para consultar `name`. Buscas amplas continuam retornando somente resumos; schemas maiores exigem consulta explícita pelo nome.
- `{ "cursor": 20, "limit": 20 }`: próxima página (máximo 50).
- `{ "name": "get_file_contents" }`: ferramenta específica e schema completo.

`mcp_github_call` e `mcp_cloudflare_call` mantêm o contrato de argumentos e normalização anteriores.

## Checklist de validação (antes de promover)

1. `npm ci`, `npm run check`, `npm run test:browser` e `npm run test:runtime` verdes no commit final (CI obrigatório).
2. Conferir CI em PR e diff — especialmente `wrangler.assistente.jsonc` de produção e preview, segredos ausentes e testes sem D1 real.
3. Publicar **somente preview** primeiro usando `npm run deploy:preview` num ambiente autorizado Cloudflare; verificar OAuth próprio de preview, catálogo pequeno, detalhe individual e leituras reais dos MCPs oficiais. Preview usa KV isolado e exige consentimento OAuth específico.
4. Validar em preview 429 de rate limiting com testes controlados e respostas de erro 413/limite upstream; testar token expirado e refresh com conta de teste. Não testar operações de escrita nos bancos pessoais.
5. Depois da aprovação de preview, `npx wrangler versions upload --config wrangler.assistente.jsonc` e confirmar qual versão foi **apenas enviada**.
6. Promover explicitamente a versão testada com `npx wrangler versions deploy --config wrangler.assistente.jsonc` ou painel Cloudflare e **confirmar 100% do tráfego** na versão; upload sozinho não publica.
7. Pós-publicação: `assistente_status`, skills, `mcp_github_tools`, `mcp_cloudflare_tools`, `get_me`, leitura GitHub e `whoami` Cloudflare. Conferir latência/erros em observabilidade e OAuth.
8. Rollback: selecionar a **versão anterior conhecida e saudável** em Workers Versions/Deployments, confirmar tráfego, e reabrir investigação no GitHub. Evitar correção direta no Worker sem commit.

**Sem credenciais Cloudflare disponíveis para o executor ou sem preview OAuth conectado:** parar após CI/PR; não alegar deploy realizado ou saúde ponta a ponta.

## Métricas de aceite

- Catálogo sem argumentos: resposta normalizada menor que 64 KiB e próxima página presente quando aplicável.
- Detalhe de ferramenta por `name` disponível sem perder schema; filtros/cursor não precisam transferir schemas de 95 ferramentas ao ChatGPT.
- Leituras oficiais corretas em GitHub e Cloudflare com OAuth real e refresh, sem anexos produzidos pelo Worker.
- Erros ou corpos grandes são recusados sem vazamento de tokens; nenhuma escrita remota repetida automaticamente.
- Comparar mediana/p95 de `remote_call` e `remote_discovery` antes/depois **sob carga semelhante**; não alegar ganho sem benchmark.
