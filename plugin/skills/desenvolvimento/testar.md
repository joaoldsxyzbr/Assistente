# Testar

1. Verifique o cenário solicitado, o erro original ou os critérios de aceitação.
2. Reutilize testes e ferramentas nativas do projeto. Prefira testes automatizados para lógica crítica.
3. Para regras novas ou correções repetíveis, escreva testes antes ou junto da implementação quando viável; siga RED → GREEN → REFACTOR onde trouxer benefício real.
4. Para pequenos ajustes visuais, use checagens visuais e funcionais; não obrigue infraestrutura de testes desproporcional.
5. Verifique casos de borda e regressões do módulo tocado. Se testes não puderem rodar, não declare sucesso total.
6. Registre comandos usados e seus resultados quando relevante.
