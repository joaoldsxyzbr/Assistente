# Planejar

1. Defina o resultado esperado e os critérios de aceitação.
2. Liste poucos passos executáveis com arquivos/áreas e dependências relevantes.
3. Inclua riscos, estratégia de teste e reversão quando houver mudança relevante.
4. Não criar arquitetura nova sem necessidade nem documentação extensa para ajuste trivial.
5. Se o usuário pediu apenas plano, pare após apresentá-lo; se autorizou executar, siga.

**Modelo compacto:** Objetivo → Mudanças → Verificação → Riscos.
