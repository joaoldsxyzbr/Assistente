# Descoberta e desenho de solução

Entenda o problema **antes** de desenhar a solução, sem virar interrogatório. Use o contexto, arquivos e decisões já fornecidos.

1. **Entender o uso real:** quem usa, tarefa, cenário atual, atrito e resultado desejado. Diferencie necessidades de preferências de implementação.
2. **Detectar lacunas:** se houver uma decisão essencial que mude a implementação, faça uma pergunta curta. Se o usuário deu autonomia, faça a melhor suposição **explícita** e siga.
3. **Alternativas:** compare duas opções somente quando houver trade-off real de custo, segurança, tempo ou experiência; prefira menor complexidade que cumpra o objetivo.
4. **Acordar critérios:** indique entradas, saídas, casos excepcionais, interfaces afetadas, limites e o que fica fora do escopo.
5. **Registrar:** para projeto complexo, produza descrição curta em arquivo ou no chat com objetivos, restrições, decisões e riscos. Para tarefa pequena, uma frase basta.
6. **Encaminhar:** quando a solução estiver definida, use `planejamento-tecnico` só se houver dependências/etapas significativas; do contrário, siga direto para `desenvolvimento` ou `ux-ui`.

Não transforme uma ordem clara em pesquisa extensa. Sem pedido de execução, não edite sistemas externos.
